# 기능 정의: F1 레이스 노트

2021~2025 시즌 F1 그랑프리 경기를 고르고 질문하면, **경기 기록 · 위키백과 · 그 시즌 FIA 스포팅 규정**을 근거로 답하고 근거 원문을 함께 보여 주는 RAG 지식 서비스.

## 1. 왜 F1인가

F1은 **근거 없이 답하면 틀리기 쉬운** 분야다. 규정이 시즌마다 바뀌고, 경기 후 판정이 번복되는 일이 잦다. 언어 모델이 기억에만 의존하면 다른 해의 규정을 섞거나 번복 전 순위를 최종 결과로 말한다.

| 질문 예시 | 근거 없이 답할 때 생기는 오류 | 필요한 근거 |
| --- | --- | --- |
| 2021 아부다비 GP 마지막 랩 세이프티카 재출발은 왜 논란이 됐나 | 어떤 차가 추월을 허용받았는지, 규정 절차가 무엇이었는지 섞어 말함 | 경기 위키 문서 + 2021 규정 세이프티카 조항 |
| 2021 벨기에 GP는 왜 절반 포인트였고 다음 시즌 규정은 어떻게 바뀌었나 | 바뀐 뒤의 규정을 2021년에 적용함 | 경기 위키 문서 + 2021·2022 규정 포인트 조항 |
| 스프린트 포인트는 2021년과 2022년에 어떻게 달랐나 | 연도별 수치를 혼동함 | 2021·2022 규정 스프린트 조항 |
| 2023 사우디아라비아 GP 알론소의 경기 후 페널티는 어떻게 처리됐나 | 번복 전 순위를 최종 결과로 말함 | 경기 위키 문서, 심판 결정문 |
| 이 경기 우승자는 몇 번 그리드에서 출발했나 | 예선 순위와 그리드(페널티 반영)를 혼동함 | 경기 메타데이터 |

## 2. 데이터 구성

| 데이터 | 출처 | 규모 · 비고 |
| --- | --- | --- |
| 경기 메타데이터 | [Jolpica-F1 API](https://github.com/jolpica/jolpica-f1) (Ergast 후속) | 2021~2023 각 22경기, 2024·2025 각 24경기 = **114경기**. 경기 1건을 검색용 텍스트 1개로 색인 |
| 경기 서술 문서 | 영어 위키백과 | 질문할 때 필요한 문서만 수집. 한국어 경기 문서는 결과표 위주라 기본값에서 제외(설정으로 추가 가능) |
| 규정 · 판정 문서 | FIA 스포팅 규정 PDF(시즌별), FIA 심판 결정문 PDF | 조항 단위로 색인. 재배포 허락을 확인하지 못해 PDF 파일은 저장소에 올리지 않음 |

출처별 라이선스와 지키는 방법은 [`05_데이터_출처와_이용조건.md`](05_데이터_출처와_이용조건.md)에 정리했다. 판정 해설·사실 판정 결과에는 "FIA 공식 판정이 아님" 안내를 붙인다.

## 3. 기능

| 영역 | 기능 | 동작 | 구현 위치 |
| --- | --- | --- | --- |
| 데이터 | 경기 데이터 적재 | 시즌·라운드·그랑프리 이름(한·영)·서킷·포디움·예선 1위·1번 그리드·폴 투 윈·패스티스트 랩·리타이어 수를 경기당 텍스트 하나로 정리 | `domain/races.py`, `scripts/build_races.py` |
| 색인 | 경기 색인 | 경기 텍스트를 `f1_races` 컬렉션에 경기당 청크 1개로 색인. 청크 ID = 경기 ID라 다시 색인해도 개수가 늘지 않음 | `store/vectorstore.py`, `scripts/index_items.py` |
| 수집 | 검색어 추출 → 문서 수집 | ① 경기 정보와 질문에서 위키백과 검색어를 JSON으로 추출 ② 후보(제목+요약)를 모아 색인할 문서만 선별 ③ 이미 수집한 검색어는 건너뜀. 경기 자체 문서는 선별 결과와 상관없이 항상 색인 | `rag/collector.py`, `sources/wiki.py` |
| 색인 | 문서 청킹 | 위키는 섹션 경계를 지키며 1,000자 / 200자 중복, 규정은 조항 단위로 자름. 청크 ID는 `경기ID:문서ID:순번` | `store/chunking.py`, `domain/regulations.py` |
| 검색 | 근거 검색 · 병합 | 경기 메타데이터는 항상 근거 1번. 경기 문서와 그 시즌 규정을 **따로** 검색한 뒤 합치고 중복 제거(규정이 경기 문서를 밀어내지 않게). 기본 MMR 검색(후보 30건 중 6건, λ=0.7) | `rag/retriever.py` |
| 생성 | 근거 기반 답변 | LangGraph `retrieve → generate` 두 노드. 검색된 근거만 써서 답하고, 근거가 없으면 "제공된 문서에서 확인되지 않습니다"라고 답함 | `rag/graph.py`, `rag/prompts.py` |
| 생성 | 근거 표시 | 답변 본문의 [근거 n] 중 **실제로 인용된 근거만** 제목·출처 종류·원문 URL(PDF는 파일명과 쪽)과 함께 표시 | `rag/citations.py` |
| 서비스 | 판정 해설 · 사실 판정 | 사건을 상황 / 관련 규정 / 실제 판정 / 확인 안 되는 부분으로 해설. 주장을 사실 / 거짓 / 일부 사실 / 확인 불가로 판정 | `domain/profile.py`, `services/qa.py` |
| 서비스 | 조건으로 경기 찾기 | 자연어 조건으로 후보를 찾고 LLM이 조건에 맞는 경기만 고름. '최종전'처럼 의미 검색이 놓치기 쉬운 조건은 해당 경기를 후보에 강제로 포함 | `services/explore.py` |
| 화면 | 두 가지 화면 | Streamlit 화면과, FastAPI 서버 + HTML/CSS/JS 화면. 진행 상태를 NDJSON 스트림으로 받아 S1 수집 · S2 검색 · S3 생성 섹터로 표시, 근거 번호를 누르면 원문 패널 | `ui/`, `api/`, `web/` |
| 품질 | RAG 전후 비교 | 대표 질문 10개를 RAG 없이 / RAG로 답하게 해 정확성 · 근거 제시 · 모름 응답 비교 | `scripts/evaluate_rag.py` |

## 4. 품질 · 안전 기준

| 기준 | 내용 | 확인 방법 |
| --- | --- | --- |
| 응답 시간 | 대표 질문 30초 미만. 같은 질문은 캐시를 쓰고, 경기 자체 문서를 미리 수집해 첫 질문 시간을 줄임. 단계별 시간을 답변 아래 표시 | `verify.py`, 화면의 처리 시간 |
| 수집 캐시 | (경기, 질문) → 검색어, (경기, 검색어) → 수집 결과를 저장해 다시 수집하지 않음 | `rag/cache.py`, 테스트 |
| API 키 관리 | 키는 `.env`로만 받고 `.gitignore`로 제외. 소스에 키 형식 문자열이 없는지 자동 검사 | 테스트 `test_no_api_keys_in_source` |
| 오류 정보 비노출 | 화면에는 안내 문구와 오류 번호만, 상세는 `logs/app.log`에만 기록. 프롬프트 전문과 키는 응답에 넣지 않음 | 테스트 `test_unexpected_error_is_masked` |
| 모듈 분리 | 데이터 준비(`domain/`, `sources/`) · Vector Store(`store/`) · RAG(`rag/`) · 서비스(`services/`) · 화면(`ui/`, `api/`, `web/`). F1에 묶인 코드는 `domain/`에만 둠 | 폴더 구조 |
| 외부 API 예절 | 같은 호스트 호출 간격 최소 1초, 429·5xx는 지수 백오프와 Retry-After 준수, 연락처가 든 User-Agent | `sources/http.py`, 테스트 |
| 출처 표시 | 데이터별 출처 · 라이선스 기록, 근거마다 원문 URL 표시 | `docs/05_데이터_출처와_이용조건.md` |
