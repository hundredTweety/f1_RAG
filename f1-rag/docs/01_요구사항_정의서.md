# 요구사항 정의서: F1 레이스 노트

F1 2021-2025 시즌 그랑프리 경기를 고르고 질문하면, 경기 기록·위키백과·그 시즌 FIA 스포팅 규정을 근거로 답하고 근거 원문을 함께 보여 주는 RAG 지식 서비스다. 필수 F2001-F2012와 심화 F2013-F2016을 모두 구현했다.

## 1. 도메인 확정 (2.1)

| 조건 | 내용 | 충족 근거 |
| --- | --- | --- |
| 항목 메타데이터 약 100건 이상 | 2021-2025 시즌 그랑프리 결선. 경기 1건 = 항목 1건 | 2021·2022·2023 각 22경기, 2024·2025 각 24경기로 **114경기**. 실제 실행에서 로드 114건 = 색인 청크 114개, 두 번 색인해도 114개로 확인 (`docs/results/verification_report.md` 4.1) |
| 메타데이터 출처 | [Jolpica-F1 API](https://github.com/jolpica/jolpica-f1) (Ergast 후속, JSON) | 일정·결선 결과·예선 결과·그리드·완주 상태를 경기 단위로 제공 |
| 항목마다 연결되는 외부 문서 | ① 영어 위키백과 경기 문서 ② 시즌별 FIA 스포팅 규정 PDF ③ (선택) FIA 심판 결정문 PDF | 경기별 위키 문서 존재 여부는 `build_races.py`가 `data/processed/wiki_coverage.csv`로 기록한다. 명세서가 권장하는 한국어 위키백과는 경기 문서 대부분이 결과표 위주이고, 영어 문서와 섞으면 이름 표기·서술이 엇갈려 기본으로는 쓰지 않는다(설정으로 추가 가능, 설계문서 10절) |
| 출처와 이용 조건 기록 | `docs/05_데이터_출처와_이용조건.md` | Jolpica CC BY-NC-SA 4.0(비상업), 위키백과 CC BY-SA 4.0, FIA 문서는 링크만 제공 |
| 근거 없이 답하면 틀리기 쉬운 질문 | 아래 표 | 연도별 규정이 자주 바뀌고, 판정이 경기 후 번복된 사례가 많다 |
| 위험 도메인 여부 | 아님 (건강·금융처럼 판단을 대신하면 위험한 도메인이 아님) | 면책 안내는 필수가 아니지만, 판정 해설·사실 판정 결과에는 "FIA 공식 판정이 아님" 안내를 붙인다 |

**근거 없이 답하면 틀리기 쉬운 질문**

| 질문 | 근거 없이 답할 때 생기는 오류 | 필요한 근거 |
| --- | --- | --- |
| 2021 아부다비 GP 마지막 랩 세이프티카 재출발은 왜 논란이 됐나 | 어떤 차가 추월을 허용받았는지, 규정 절차가 무엇이었는지 섞어 말함 | 경기 위키 문서 + 2021 규정 세이프티카 조항 |
| 2021 벨기에 GP는 왜 절반 포인트였고 다음 시즌 규정은 어떻게 바뀌었나 | 바뀐 뒤의 규정을 2021년에 적용함 | 경기 위키 문서 + 2021·2022 규정 포인트 조항 |
| 스프린트 포인트는 2021년과 2022년에 어떻게 달랐나 | 연도별 수치를 혼동함 | 2021·2022 규정 스프린트 조항 |
| 2023 사우디아라비아 GP 알론소의 경기 후 페널티는 어떻게 처리됐나 | 번복 전 순위를 최종 결과로 말함 | 경기 위키 문서, 심판 결정문 |
| 이 경기 우승자는 몇 번 그리드에서 출발했나 | 예선 순위와 그리드(페널티 반영)를 혼동함 | 경기 메타데이터 |

## 2. 기능 요구사항

필수 기능은 명세서 문구를 바꾸지 않고, 표현만 도메인에 맞췄다. 구현 위치는 `f1rag/` 기준이다.

| 번호 | 분류 | 요구사항명 | 요구사항 상세 (F1 도메인) | 우선순위 | 구현 위치 |
| --- | --- | --- | --- | --- | --- |
| F2001 | 데이터 | 항목 메타데이터 적재 | 2021~2025 시즌 경기 목록을 로드하고, 경기 1건을 시즌·라운드·그랑프리 이름(한·영)·서킷·나라·우승/2위/3위·예선 1위·1번 그리드 출발·폴 투 윈·패스티스트 랩·리타이어 수가 이어진 색인 텍스트 하나로 구성한다 | 필수 | `domain/races.py`, `scripts/build_races.py` |
| F2002 | 색인 | 메타데이터 색인(RAG 1) | 경기 텍스트를 임베딩해 `f1_races` 컬렉션에 경기당 청크 1개로 색인한다. 청크 ID = 경기 ID라 다시 색인해도 덮어쓰기만 일어난다. 화면에 색인 건수를 항상 표시한다 | 필수 | `store/vectorstore.py`, `scripts/index_items.py` |
| F2003 | 프롬프트 | 검색어 추출(프롬프트 1) | F1 해설위원 역할 프롬프트로 경기 정보와 질문에서 위키백과 검색어를 JSON 배열로 추출한다. 경기 자체 문서는 항상 검색 대상에 포함한다 | 필수 | `rag/prompts.py`, `rag/collector.py` |
| F2004 | 수집 | 외부 문서 수집(프롬프트 2) | 위키백과에서 검색어별 후보(제목+요약)를 모으고, 선별 프롬프트로 색인할 문서만 골라 본문과 원문 URL을 수집한다. 경기 자체 문서는 선별·길이 규칙보다 우선해 항상 색인한다. 이미 수집한 검색어는 다시 수집하지 않는다. 외부 호출이 막힌 환경에서는 문서 묶음(`data/offline_docs`)으로 대신한다 | 필수 | `rag/collector.py`, `sources/wiki.py`, `sources/offline.py` |
| F2005 | 색인 | 외부 문서 색인(RAG 2) | 수집 문서를 섹션 → 1,000자/200자 중복으로 청킹해 `f1_docs` 컬렉션에 색인한다. 청크에 문서 제목·섹션·원문 URL·경기 ID·검색어를 저장하고, 청크 ID는 `경기ID:문서ID:순번`이다. 청크 크기와 중복 길이는 `config/settings.yaml`에서 바꾼다 | 필수 | `store/chunking.py` |
| F2006 | 검색 | 근거 검색 및 병합 | 선택한 경기의 메타데이터 청크는 항상 근거 1번에 넣고, 그 경기 문서와 그 시즌 규정을 따로 의미 검색해(규정은 기능별 2~3개) 경기 문서가 규정에 밀리지 않게 한다. 두 컬렉션 결과를 합치고 청크 ID·본문이 같은 청크를 제거한다. Top-k는 설정으로 조정한다 | 필수 | `rag/retriever.py`, `domain/profile.py` |
| F2007 | 생성 | 근거 기반 답변 생성(프롬프트 3) | LangGraph `retrieve`·`generate` 두 노드로 구성하고, 답변 프롬프트로 검색된 근거만 써서 답한다. 근거에 출처 종류(경기 메타데이터/위키백과/FIA 스포팅 규정/FIA 심판 결정문)를 붙이고, 근거가 없으면 "제공된 문서에서 확인되지 않습니다"라고 답한다 | 필수 | `rag/graph.py`, `rag/prompts.py` |
| F2008 | 생성 | 근거 표시 | 답변 본문의 [근거 n]을 찾아 실제로 인용된 근거만 제목·출처 종류·원문 URL(PDF는 파일명과 쪽)과 함께 표시한다. 인용된 근거가 없으면 그 사실을 안내한다 | 필수 | `rag/citations.py`, `services/qa.py` |
| F2009 | UI | 항목 선택 및 질의응답 | 시즌·경기를 골라 채팅으로 묻고 답한다. 대화 기록은 경기별로 따로 유지한다 | 필수 | `ui/streamlit_app.py`, `web/` |
| F2010 | 서비스 | 도메인 특화 기능 | ① **판정 해설**: 경기 중 사건을 그 시즌 규정 조항과 함께 상황/관련 규정/실제 판정/확인 안 되는 부분으로 해설 ② **사실 판정**: F1에 관한 주장을 사실/거짓/일부 사실/확인 불가로 판정. 둘 다 색인 문서만 근거로 쓰고 근거를 함께 보여 준다 | 필수 | `domain/profile.py`(MODES), `services/qa.py` |
| F2011 | 서비스 | 조건 기반 항목 탐색 | "예선 1위가 아닌 드라이버가 1번 그리드에서 출발한 경기"처럼 자연어 조건을 입력하면 메타데이터 색인에서 후보를 찾고(연도가 있으면 그 시즌으로 먼저 좁히고, '최종전'·'개막전'이나 예선 1위와 1번 그리드 비교처럼 의미 검색이 놓치기 쉬운 조건은 해당 경기를 후보에 반드시 넣음) LLM이 조건에 맞는 경기만 골라 카드로 보여 준다. 카드를 누르면 그 경기 대화로 이어진다 | 필수 | `services/explore.py` |
| F2012 | UI | 진행 상태 및 안내 | 문서 수집·근거 검색·답변 생성 단계를 화면에 표시하고, 수집된 문서 제목을 보여 준다. 색인 0건, API 키 누락, 외부 근거 없음, 인용 근거 없음을 안내한다. 판정 기능에는 "공식 판정이 아님" 안내를 붙인다 | 필수 | `services/qa.py`, 두 화면 |
| F2013 | UI | 프론트엔드 직접 구현 | HTML·CSS·JavaScript 화면(`web/`)과 FastAPI 서버(`api/server.py`)를 분리하고, 요청·응답 형식을 `api/schemas.py`에 정의한다. 질문 입력·답변·근거 표시와 조건 탐색을 모두 제공하며, 진행 상태는 NDJSON 스트림으로 받아 S1 수집·S2 검색·S3 생성 섹터와 시각이 찍힌 로그로 보여 준다. 근거 번호를 누르면 원문 패널이 열리고, 경기를 고르면 우승 차 사진(위키미디어 공용, 출처 표시)과 기록 스트립을 보여 준다 | 심화 | `api/`, `web/` |
| F2014 | 검색 | MMR 검색 적용 | 후보 30건(fetch_k)을 가져와 그중 6건(top_k)을 다양성 기준(λ=0.7)으로 고른다. 유사도 검색과의 차이를 `scripts/compare_retrieval.py`로 확인한다 | 심화 | `rag/retriever.py` |
| F2015 | 품질 | RAG 전후 품질 비교 | 대표 질문 10개(eval/questions.yaml)를 RAG 없이·RAG로 답하게 하고 사실 정확성·근거 제시·모름 응답을 비교해 `docs/04_RAG_전후_비교.md`를 만든다 | 심화 | `scripts/evaluate_rag.py` |
| F2016 | 수집 | 여러 문서 출처 결합 | 위키백과(서술형)와 FIA 규정 PDF(조항형), 심판 결정문 PDF를 한 컬렉션에 색인하고 근거에 출처 종류를 구분해 표시한다. 규정은 조항 단위, 위키는 섹션+길이 기준으로 다르게 청킹한다 | 심화 | `domain/regulations.py`, `sources/pdf.py`, `scripts/index_pdfs.py` |
